# FE 인증 화면 ↔ BE API 연결 점검

확인 기준: FE `develop`의 `lib/features/auth/presentation/` 화면과 BE `feature/auth`의 [인증 API 계약](auth-api.md). 2026-10-03 기준 **화면은 UI 미리보기이고 실제 API 연결은 아직 없다.** FE 팀의 화면 파일을 이 문서 작업에서 수정하지 않았다.

| 화면/동작 | 현재 FE | BE 계약 | 연결할 때 필요한 작업 |
| --- | --- | --- | --- |
| COBIA 표기·필수 약관 2개 | 화면에 반영됨 | 가입 요청에 두 동의값 `true` 필요, 서버가 동의 시각 기록 | 체크값을 가입 요청으로 보내기 |
| 이메일 인증번호 발송 | 350ms 대기 뒤 무조건 발송 성공처럼 표시 | `POST /api/auth/email-verifications/send`; 202, 5분 만료·60초 재전송 제한·메일 실패 오류 | HTTP 호출 후 202에서만 입력창 열기. 응답의 시간으로 타이머 표시. 429/503 처리 |
| 이메일 인증번호 확인 | 아무 6자리 숫자면 인증 완료 | `POST /api/auth/email-verifications/confirm`; 실제 코드가 맞아야 `verified: true` | 서버 응답 성공 후에만 인증 상태 변경. `INVALID_CODE` 표시 |
| 이메일 수정 | 인증 상태를 해제함 | 다른 이메일은 재인증 필요 | 현재 동작 유지 |
| 회원가입 입력 | **닉네임 필드 없음** | `nickname` 2~50자 필수, DB에서도 NOT NULL·UNIQUE | FE에 닉네임 입력과 중복 오류 표시 추가. 가입 API에서 필드를 생략할 수 없음 |
| 비밀번호 검증 | 비어 있지 않으면 허용 | 8~64자 | FE 안내/검증을 같은 길이로 맞추고 서버 `INVALID_REQUEST` 표시 |
| 회원가입 제출 | 350ms 대기 후 완료 화면 | `POST /api/auth/register` 201일 때 완료 | 서버 성공 후에만 이동. 이메일/닉네임 중복·인증 만료 오류 처리 |
| 로그인 | 350ms 대기 후 홈으로 이동 | `POST /api/auth/login`; Access JWT·Refresh Token·사용자 정보 반환 | API 호출, 토큰 안전 저장, 실패 메시지 처리 후 홈 이동 |
| 토큰 재발급·로그아웃 | 현재 인증 세션 연결 없음 | `/api/auth/refresh`, `/api/auth/logout` | 만료 시 1회 재발급, 실패 시 로그인 이동. 로그아웃 시 서버 호출·로컬 토큰 삭제 |
| 화면 접근 제어 | 로그인 화면에서 시작하지만 홈 등 경로를 직접 열 수 있음 | 보호 API는 JWT 필요 | 로그인 여부에 따라 보호 화면 이동을 막는 `go_router` redirect 추가 |
| 비밀번호 찾기 화면 | 이메일→코드→새 비밀번호→완료 UI 있음. 현재는 모두 미리보기 | **이번 BE 인증 API에는 비밀번호 재설정 엔드포인트 없음** | 별도 API 설계·구현 전에는 실제 변경 성공으로 연결하지 않기. 회원가입 인증 코드와 재설정 코드를 같은 목적으로 재사용하지 않기 |

## 연결 순서 추천

1. FE가 가입 화면에 **닉네임**과 8~64자 비밀번호 안내를 추가한다.
2. 이메일 발송·확인 API를 연결하고, 서버 성공 전에는 인증 완료를 표시하지 않는다.
3. 회원가입과 로그인 API를 연결한다. 이때 오류 코드별 문구와 토큰 저장 방식을 함께 적용한다.
4. 로그인 세션을 `go_router`에 연결하고 재발급·로그아웃을 붙인다.
5. 비밀번호 재설정은 **별도 기능/커밋**으로 BE API를 구현한 뒤 화면과 연결한다.

BE의 `docs/auth-api.md`가 요청·응답 필드의 기준이다. 이 표는 FE 최신 화면과의 차이를 설명하며, 미구현 화면을 구현 완료라고 표시하지 않는다.
